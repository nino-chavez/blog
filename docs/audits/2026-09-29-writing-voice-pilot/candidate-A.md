# The Work Doesn’t End at Send

The question began with coding agents that can produce more code than a person can comfortably review. Then it widened: what happens when a personal assistant makes it easy to write more emails, schedule more meetings, and send more follow-ups?

Jevons paradox is one way to frame the risk. In the nineteenth century, William Stanley Jevons argued that making coal use more efficient could expand demand because it made coal profitable in more places—not simply reduce consumption. [His argument](https://www.econlib.org/library/YPDBooks/Jevons/jvnCQ.html?chapter_num=9) does not prove that AI assistants will create more work. It describes a mechanism worth watching.

An assistant can make a request cheap to compose without making the recipient’s decision cheap to make. A hypothetical assistant might draft a proposal, send a reminder, and schedule a meeting that its user would otherwise have postponed or dropped. The recipient still has to read it, decide, coordinate, and act. Faster replies do not remove the commitment underneath them.

That is the possible shift: saved effort for the sender becomes new work distributed across everyone else in the conversation.

## What the comparison would test

The useful comparison is not between an AI-written message and a human-written one. It is between whole conversations with and without the assistant.

A pilot could track drafting time, but also completed useful decisions, commitments created, recipient effort, and unnecessary exchanges avoided. The question is whether the assistant helps a request reach a real resolution—or simply makes it easier to create another open loop.

That distinction matters because more visible activity is not automatically more useful work. [Cal Newport’s argument](https://bigthink.com/series/the-big-think-interview/cal-newport-burnout/) is that work improves when attention goes to fewer, better commitments rather than an ever-growing list of simultaneous ones. That is not evidence about AI assistants. It is a useful standard for judging them.

The countercase is real, even if it remains hypothetical here. An assistant might resolve a routine exchange, filter a weak request before it reaches anyone, or prevent a meeting that would have happened anyway. In those cases, the tool could reduce work on both sides.

The problem is not that an assistant sends more messages. The problem would be treating faster composition as proof that the conversation got cheaper. The decision is still somewhere in the room.
