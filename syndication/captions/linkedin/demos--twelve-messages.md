Four days before a grass volleyball tournament, the team list existed in two places that disagreed. A Google Form's raw responses and a hand-curated tab. Spelling variants of the same captain. One player's name filed in the team-name column. The tournament database still held five test teams from an earlier dry run, and the graphics pipeline was still rendering placeholder names.

All of it cleared in one working session. I typed twelve messages.

None of the twelve is production work. They are direction, correction, a challenge, a taste call, and one word authorizing publish. The agent read both sheets through an authenticated browser, resolved the conflicts and the misfiled name, deleted the five test teams, and wrote ten real ones through the product API. Then it built three countdown templates and published two.

The fifth message was that the countdown looked too derivative of everything already posted. That is a creative rejection with a constraint attached, and it only means something because the brand is a versioned file the agent reads at the start of every session rather than a paragraph in a prompt. Three genuinely different directions came back in one pass.

The eighth was a question: why three folders at all? The agent had justified that structure from an assumption it never checked. The repo's actual convention was one folder per event.

What makes this repeatable is not the message count. It is that the deliverable was never a graphic. Every asset is a parameterized HTML template compiled to PNG, reading from a roster file, which reads from the product database. A team drops out, the number changes everywhere, and nobody opens an image editor. Ten roster cards cost what one costs.

The failure is worth more than the demo. A wildcard delete during cleanup wiped the output folders, including two assets already live. The publish ledger pointed at object storage and both came back byte-for-byte identical. One render that had never been published sat outside every safety net. It is gone, and the deck says so rather than rounding it off.

Then the Instagram Stories API turned out to accept bare media only. No captions, no tags. The credit request was impossible at publish time, so it moved down a layer into the template pixels, where every future asset carries it whether or not anyone remembers to ask.
